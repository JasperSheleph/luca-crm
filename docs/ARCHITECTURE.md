# Architecture

*How the pieces fit together. [`PROGRESS.md`](PROGRESS.md) says what is built;
this says how it works. Verified against the code, not remembered.*

## Stack

- **Next.js 16** (App Router, Turbopack) · **React 19** · **TypeScript** · **Tailwind v4**
- **Supabase** — Postgres, Auth, Storage, Row Level Security, `pg_cron` + `pg_net`
- **WhatsApp Cloud API** — the only external service, behind a feature flag, currently off
- No other third-party dependencies. Deliberate: there is no full-time maintainer,
  so nothing that needs version upkeep

## Systems

| System | Used for | Auth |
|---|---|---|
| Supabase Postgres | All data — 19 tables, 14 migrations | Session JWT (RLS) or service-role key |
| Supabase Auth | Sign-in, password links | Email/password; a mobile resolves to the email |
| Supabase Storage | Quote files, visit photos — 2 **private** buckets | Short-lived signed URLs |
| `pg_cron` + `pg_net` | Scheduled jobs → `POST /api/cron` | Shared `CRON_SECRET` |
| WhatsApp Cloud API | Staff alerts only, flagged off | Meta token in env vars |
| Meta Lead Ads | CSV export, uploaded by hand | None — no API integration |

## Layers

- `app/` — routes only. Rendering and layout, nothing else
- `components/` — presentational. **No DB calls, no business rules**
- `lib/domain/` — pure business rules. No DB, no React. **206 unit tests live here**
- `lib/queries/` — every database read · `lib/actions/` — every database write
- `lib/db/` — `server.ts` runs as the user so RLS applies; `admin.ts` bypasses RLS entirely
- `lib/notifications/` — `notify()` is the **only** way anyone is told anything
- `supabase/migrations/` — forward-only, never edited once applied

Every stage change goes through `lib/domain/stages.ts`. Every permission check
goes through `lib/domain/permissions.ts`. There is no second path to either.

## Roles

- **Admin** — everything. A deliberate superset of CRM Manager, so the owners can
  cover absence
- **CRM Manager** — the hub. Qualifies, assigns, verifies, quotes, closes
- **Sales Rep** — own deals only, enforced by RLS rather than hidden UI

## Pages

**Everyone**

- `/login` — mobile number **or** email, plus password. Digits resolve to the
  account server-side via `phone_normalized`; an unmatched mobile fails
  identically to a wrong password, so it is not an enumeration oracle
- `/reset-password` + `/auth/confirm` — one-time token, generated by an admin and
  handed over in person. **Nothing is ever emailed**
- `/notifications` — in-app alert centre, scoped to the recipient
- `/account` — own profile, change password

**Admin only**

- `/admin/dashboard` — leads by source and campaign, contact and drop rate,
  funnel, win rate, conversion by rep, cycle time, **lead age at first contact**,
  stalled deals, failed verifications by rep. Mobile-first, stacked cards
- `/admin/users` — create, deactivate, change role, generate a password link.
  Mobile mandatory and unique. Guards: cannot remove your own admin, cannot leave
  the system with zero admins
- `/admin/settings` — dropdown lists (add, rename, reorder, hide — **no delete
  anywhere**), app settings through typed controls rather than raw JSON, and
  notification rules. **Template text is read-only** because Meta approves it
- `/admin/import` — Meta CSV and legacy tracker. Choose a file, the preview
  appears by itself, one button writes
- `/admin/health` — plain language: last import, WhatsApp state, failed jobs,
  storage and database usage

**Admin + CRM Manager**

- `/deals` — the main working screen. Search by phone or name; multi-select
  filters on stage, owner, source, city and verification; **10 sort orders**;
  **5 work-queue presets** (To call · Visit not yet confirmed · Overdue · Parked
  leads due today · Quotes past SLA); bulk assign; CSV export
- **Lead slide-over** — opens over the list, non-modal, list stays interactive.
  `?lead=<id>` written with the History API so it is linkable and refresh-safe
  without re-running the page's queries. Escape closes, arrows step between
  leads, full-screen on a phone
- `/deals/[id]` — full detail. The **activities timeline is the centrepiece**:
  append-only, and the direct replacement for their spreadsheet Remarks column

**Sales Rep**

- `/today` — appointments today plus overdue actions
- `/my-deals` — RLS-scoped. Another rep's deal returns **404, not a hidden element**
- Deal detail — log calls, confirm or reschedule appointments, check in and out
  with geolocation, upload photos

## API

- `GET /api/deals/[id]` — slide-over payload. Runs as the user, so RLS applies
- `GET /api/files?bucket=&path=` — short-lived signed URLs for the private buckets
- `GET /deals/export` — CSV of the current filtered view, with Excel-safe phone escaping
- `POST /api/cron` — job runner. Refuses without `CRON_SECRET`; 503 if unset
- `GET /auth/confirm` — one-time password token exchange
- `POST /api/leads/inbound` — **specified but NOT built.** See open items in `PROGRESS.md`

## Data flows

**Lead arrives (CSV import).** Upload → parse and normalise → preview, nothing
written → confirm → raw payload to `inbound_leads_raw` **before processing** →
match customer on normalised phone → create or reuse the customer → create the
deal in `qualifying` → auto-assign per `lead_assignment_mode` → write the
`assignments` row.

**Call logged, one click.** Disposition button → `activities` row → sets
`first_contacted_at` if it is the first → clears the reminder it answered →
`notify()` if a rule matches → both the list and the drawer refresh.

**Stage change.** `canTransition()` validates → deal updated → writes
`deal_stage_history` **and** an `activities` row → `notify()`. The gates:
booking an appointment needs the required fields, **Quote Sent needs verification
confirmed**, and Won needs the advance recorded.

**Visit → verification → quote.** Rep checks in with GPS → checks out with photos
→ the deal moves itself to Site Visit Done with verification `pending` → it
appears in the CRM Manager's queue → she calls and records: **confirmed** (a
quote can now go out) · **failed** (the deal *freezes* and both admins are
alerted immediately) · **unreachable** (escalates after the configured hours).
Only an admin resolves a failure, and the note is mandatory.

**Notification.** Event or cron → `notify()` → always writes `notifications_log`
and the in-app centre → if `whatsapp_enabled` **and** credentials exist, also
sends WhatsApp → failures are recorded, never thrown.

**Scheduled jobs.** `pg_cron` → `pg_net` POST → `/api/cron` with the secret → due
rules evaluated in **Asia/Kolkata** → nurture wake-ups, overdue actions, quote
nudges, verification escalation, the 7pm digest.

## Security

- **RLS on every table.** Reps are scoped through the parent deal on every child table
- `activities`, `deal_stage_history` and `assignments` have **no update or delete
  policy at all** — append-only holds even for admins
- `inbound_leads_raw` and `audit_log` have RLS with **zero policies**: service-role only
- **Grants are not automatic.** "Expose new tables" is off, so a new table is
  invisible to everyone until explicitly granted
- Both storage buckets are private; tables store the path, never a URL
- The service-role key is server-only, guarded by the `server-only` package
